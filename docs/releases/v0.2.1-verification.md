# Windows v0.2.1 验证记录

日期：2026-10-25。Windows x64、Tauri 2 / WebView2、Rust MSVC、Node.js 24。

## 登录检查修复

- 检查登录与扫码流程分离。检查脚本不会点击登录入口、刷新二维码或把二维码过期当作账号失效；只有稳定的本人账号控件才确认登录有效，笔记作者链接不能冒充本人账号。
- 页面加载失败、要求验证或无法确认时返回“暂时无法确认”，前端展示明确结果，保留加密会话、账号名称与头像。检查结果不再通过“是否保存了 Cookie”推断。
- 恢复已保存会话时只补充网页缺少的 Cookie，保留网页里更新的值。Windows 原生写入保留平台域名前导点，使会话可用于 www 子域；登录凭据使用 HttpOnly，页面脚本令牌保持可读。浏览器会话导入复用同一写入方式。
- 登录检查与主动退出使用同一平台锁，并检查请求代次，避免已取消的检查在退出后写回旧会话。

## 自动与原生回归

- 前端 80 项测试通过；TypeScript 检查和 Vite 生产构建通过。新增只读检查、二维码过期、本人控件、保留账号界面等回归。
- Rust 67 项测试通过，5 项联网或速度基准测试默认忽略。覆盖加密会话、缺失 Cookie 恢复计划、稳定登录证据，以及既有解析、任务、断点续传、更新校验和多连接下载。
- 在独立应用标识、WebView 资料和加密会话目录中运行真实 Windows 客户端，通过受控官方域名响应模拟未登录、过期二维码、本人账号和验证码，不访问用户账号。真实点击设置中的“检查登录”，确认提示保留账号，原始加密文件保持字节一致，登录入口点击次数为零。
- 模拟 WebView 中没有 Cookie 但加密会话仍存在，验证会话成功恢复；出现稳定本人账号证据后返回有效。模拟检查与主动退出并发，确认原有会话被清除且不会重新写回。原生渲染截图确认账号面板保留，检查提示与按钮显示正常。
- 使用虚构的抖音和小红书会话分别调用浏览器导入链路，随后从真实 WebView CookieManager 读回，确认 www 页面可读取登录 Cookie、凭据标记为 HttpOnly、a1 脚本令牌未标记 HttpOnly；测试后退出并清除隔离会话。全部原生回归通过。
