# SnowDown v0.2.7 安装更新紧急修复验证

日期：2026-10-25，Windows x64。桌面 v0.2.7，插件保持 v0.1.3。

用户日志显示 v0.2.5 的后端 `exit=0; stage=complete`，随后外层报文件校验失败。归档包回归确认：原清单中的主程序摘要来自独立 EXE，与实际 NSIS 中的安装版 EXE 不同，其余 16 项资源相同。Tauri 打包时更改安装类型标记，原先重新编译 NSIS 的集成测试没有覆盖这一差异。

本次改为从实际 NSIS 负载提取全部受管理文件并生成摘要清单。运行时继续逐文件校验；错误日志增加具体文件、预期和实际摘要，不放宽校验。

验证结果：

- 前端 13 个文件、102 项测试通过，TypeScript / Vite 生产构建通过。
- `cargo test --locked --manifest-path src-tauri/Cargo.toml --lib`：74 项通过、5 项公网或专项测试默认忽略。依赖锁定版本保持不变。
- 安装器核心 28 项断言通过，包括合法摘要、真实文件损坏拒绝、缺失资源拒绝和具体诊断。
- `tests/installer-manifest.ps1` 直接读取公开归档 v0.2.5 包，复现主程序摘要不一致，修正版生成的 17 项摘要匹配实际负载。
- 最终分发文件 `SnowDown_0.2.7_x64-setup.exe` 通过 `tests/installer-payload.ps1`：内嵌负载摘要、全部 17 项受管理文件、自身 `VerifyManifest` 及应用/安装器版本一致性校验均通过。此检查直接读取最终安装器，没有重新编译 NSIS，也没有执行生产安装或修改用户注册表。正式构建现在自动执行该检查。
- 安装版负载中的 EXE 摘要为 `96d2e0d4861e85251a49a593453e057eeee133516fa97552f290c6c137814259`；独立 EXE 摘要为 `982192dfbaaaabf4e9236dbb3f3ab1f5f4e2a665d597fd956949d68da00ab52b`。两种字节差异是打包类型标记造成的，分别按各自实际文件验证。免安装目录、ZIP 中的程序和本机常用目录均匹配独立 EXE。
- 本机已普通启动 v0.2.7；更新前确认没有活跃下载，原有 1 条已取消记录和 2 条已完成记录保留。未清理账号、设置或已下载内容。
