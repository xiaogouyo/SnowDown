# 安装完成后误报文件校验失败

2026-10-25 收到 v0.2.5 更新日志：安装到 `F:\ggdown\SnowDown`，后端返回 `exit=0; stage=complete`，随后外层安装器抛出“安装文件校验未通过”。

## 原因与证据

直接解出归档的 `release/SnowDown_0.2.5_x64-setup.exe` 内嵌 NSIS 负载，逐项比较其实际文件与安装器内嵌清单：17 项中只有主程序不一致，16 项资源一致。

- 清单及免安装版 EXE：`ab500f8aefaff0773254b3b153b5e9c85875e3b91df3166eadadf83c05ab155c`。
- NSIS 实际携带的 EXE：`74439de0e84156cdad4c9cec66333a1be1122fb5ed3ad90ba23159ff9c9cfc70`。
- 两个文件大小均为 13,378,560 字节，仅偏移 `0xa1e2ae` 至 `0xa1e2b0` 的 3 字节不同：`__TAURI_BUNDLE_TYPE_VAR_UNK` 变成 `__TAURI_BUNDLE_TYPE_VAR_NSS`。
- 本机依赖 `tauri-utils-2.10.2/src/platform.rs` 明确说明该标记在打包时由二进制补丁修改。打包后恢复的独立 EXE 与 NSIS 内的最终文件摘要不同。
- 原先的集成测试重新编译 NSIS 脚本，引用的是恢复后的独立 EXE，因此没有覆盖实际发布负载的这一差异。已有 v0.2.6 包也存在同类清单错误。

这能解释安装后端成功、外层校验失败的日志，不要求假设用户下载损坏。外层失败会阻止自动重启，不代表后端没有复制程序文件。

## 修正

安装器构建时使用 7-Zip 读取实际 NSIS 负载，对其中的主程序和全部受管理资源计算 SHA256，生成内嵌清单。保留严格逐文件校验；失败时将文件名、预期及实际摘要写入日志，并在提示中显示失败文件名。

7-Zip 仅为构建依赖，可通过 `SNOWDOWN_7ZIP` 指定可执行文件；使用安装包的用户无需安装。构建不会执行生产负载，也不会修改用户安装目录。

## 验证

- `tests/installer-manifest.ps1`：直接使用原始 v0.2.5 公开归档，确认修正后取得实际 NSIS 主程序摘要及相同的 16 项资源摘要。
- 安装器核心 28 项断言通过，包括合法清单、真实摘要不匹配的拒绝、缺失资源的拒绝及具体诊断日志。
- 从真实 v0.2.6 NSIS 负载解出全部文件，用修正版安装器自身的 `VerifyManifest` 校验通过，共 17 个受管理文件。
- `tests/installer-integration.ps1` 全部通过：真实 v0.1.10 主程序覆盖升级、旧版本注册信息、无历史清单、中文空格目录、组件占用时写入前拒绝、运行中程序保护、自动更新等待与重启、旧文件清理、重装与卸载。Cookie、设置、任务及下载哨兵文件内容均保留。

修正仅涉及安装器构建、文件校验诊断及对应回归测试。

## 本地修正版交付

`release/installer-fix-20261025/SnowDown_0.2.6_x64-setup.exe`，33,362,944 字节，SHA256：`39ab0a1e180c03c8675a760ceb32bab9cffeb0abd64bf38b141e9d37069eb7bc`。

该包内的应用与浏览器插件沿用 v0.2.6 原生产负载，修正外层校验清单与诊断。最终交付包再次通过自身对真实生产负载全部 17 项文件的校验，以及内嵌负载 SHA256 检查。构建目录的当前安装器已同步修正；原 `release/` 根目录归档保留，未修改线上发布。

受影响用户退出 SnowDown 后，将修正版覆盖安装到原目录即可。
