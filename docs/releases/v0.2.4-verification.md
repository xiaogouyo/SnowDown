# SnowDown v0.2.4 / 插件 v0.1.1 验证记录

日期：2026-10-25。Windows x64、Tauri 2 / WebView2、Rust MSVC、Node.js 24、独立 Chromium 扩展资料。

## 桌面速度改进

- 两个解析路径并行，并且只接受成功结果；先失败的路径不会阻断另一个路径。直连限定为 7 秒，网页元数据阶段上限 18 秒，轮询从 750ms 调整为 200ms。成功后或竞争取消时停止后台解析页。上述为各阶段预算，排队、Cookie 恢复和短链接跳转可能另需时间，不宣称全链路固定耗时。
- 同平台解析请求串行协调并复用短期结果；默认画质仅复用已确认最高画质缓存，不将较低画质冒充最高画质。会话值未改变时避免重新加密落盘和清空媒体缓存，账号变更仍清空缓存。
- 检查登录保留稳定本人控件验证，至少两次采样且超过 700ms；轮询间隔缩至 150ms，页面检测阶段预算 7 秒。与平台解析冲突时等待 350ms 后提示忙碌，原会话保留。
- 只有同一 Cookie 且最近 20 秒内已确认有效的检查结果可复用，结果明确显示“最近已确认”。扫码、取消、退出和浏览器账号导入会使旧确认失效。
- 真实隔离 Windows 客户端通过受控官方页面回归：首次确认约 805ms，重复确认 0ms；二维码过期、验证码、未知状态保留会话，Cookie 恢复、两平台导入和退出竞态保护均通过。这些是夹具测量，不代表用户真实网站的网络延迟。

## 范围与复现

`npm test`、`npm run build`、`cargo test --manifest-path src-tauri/Cargo.toml --lib --locked`。实际扩展回归为 `tests/extension.browser.mjs`，需先打包插件、提供 `.tools/v024-fixture.mp4` 并安装 Playwright，或通过 `SNOWDOWN_PLAYWRIGHT_PATH` 指定其 index.mjs。原生登录夹具使用 Debug 的 `SNOWDOWN_LOGIN_CHECK_VERIFY` 与独立应用资料。

普通网页悬浮只在获得资源模式站点授权后注入；浏览器系统页、未授权网页、不可见视频、DRM、直播或尚未加载资源不保证检测和下载。浏览器原生弹出窗口的系统阴影由浏览器管理，本版修复其内容外框。原生账号登录与公网三平台的所有变体未重新逐一验证，验证码仍可能要求用户处理。
